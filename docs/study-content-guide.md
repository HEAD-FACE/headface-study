# คู่มือนำเข้าเนื้อหา HEADFACE Study (ก่อนมีหน้า Content Studio)

ใช้กับ Admin Import API (สัญญาละเอียดดู [study-api-contract.md](study-api-contract.md) หัวข้อ 3)
เนื้อหาเข้าระบบเป็น **Draft เสมอ** → ตรวจ → In Review → Published นักเรียนเห็นเฉพาะ Published

## 1. เขียนไฟล์เนื้อหา

ไฟล์ JSON หนึ่งไฟล์ต่อหนึ่งวิชา โครงคือ วิชา → หน่วย → **บท** → **กิจกรรม (node = วงกลม 1 วงบนเส้นทางเรียน)** + คลังโจทย์ + Mock Exam 1 ชุด
ตัวอย่างเต็มที่ใช้ความสามารถครบ: [examples/study-content.sci-mock.json](examples/study-content.sci-mock.json) (ผ่านตัวตรวจของ Backend จริง 0 ข้อผิดพลาด 0 คำเตือน)
ตัวอย่างรูปแบบเรียบง่าย (บทเขียนด้วย `blocks` อย่างเดียว ระบบแปลงเป็นกิจกรรมให้เอง): [examples/study-content.sample.json](examples/study-content.sample.json)

### กิจกรรม (node) — 1 วงกลม = 1 อย่าง

| ชนิด | คืออะไร | ผู้เรียนต้องทำอะไรให้ "เสร็จ" |
|---|---|---|
| `content` | ชุดเนื้อหาเรื่องเดียวกัน แบ่งเป็น **หลายหน้า** (`pages`) ไม่จำกัดเนื้อหาต่อหน้า | อ่านแล้วกด "จบเนื้อหา" |
| `quiz` | Quiz 1 ชุด (โจทย์ที่ผูกกับ node นี้ สุ่ม `quizSize` ข้อ) | ทำ 1 ครั้งให้ถึงเกณฑ์ (`passPct`) |
| `practice` | Practice 1 ชุด (ฝึกเอง ดูเฉลย กดทำถูก/ผิด) | ไม่บังคับ — ไม่นับว่าบทเสร็จ |

- บทหนึ่งมีกี่วงก็ได้ ชนิดใดก็ได้ เรียงตามลำดับในไฟล์ (เช่น เนื้อหา 2 ชุด → Quiz → Practice → Quiz อีกชุด)
- **บทเสร็จ** เมื่อทุกชุดเนื้อหาจบ **และ** ทุก Quiz ผ่านเกณฑ์ (Practice ไม่นับ)
- บนหน้าวิชาแต่ละบทแยกสีและมีเส้นคั่น ส่วนวงกลมเรียงเป็นเส้นทางซิกแซก

```json
{ "id": "sci-l01", "no": 1, "title": "สถานะของสสาร", "quizSize": 4, "quizPassPct": 50,
  "nodes": [
    { "id": "sci-n01", "type": "content", "title": "สสารและ 3 สถานะ", "pages": [
        { "title": "สสารคืออะไร", "blocks": [ { "type": "paragraph", "text": "…" }, { "type": "figure", "kind": "image", "url": "assets/study/sci/states-of-matter.svg", "alt": "…", "caption": "…" } ] },
        { "title": null, "blocks": [ { "type": "figure", "kind": "video", "url": "https://youtu.be/XXXXXXXXXXX", "caption": "…" } ] } ] },
    { "id": "sci-z01", "type": "quiz", "title": "Quiz: สถานะของสสาร", "quizSize": 4, "passPct": 60 },
    { "id": "sci-p01", "type": "practice", "title": "ฝึก: สถานะของสสาร" } ] }
```

โจทย์ผูกกับชุดด้วย `"node": "sci-z01"` (ไม่ต้องใส่ `lessonNo` ถ้าใส่ `node`); ถ้าบทมี Quiz ชุดเดียวไม่ต้องระบุ `node` แต่ถ้ามีหลายชุดต้องระบุทุกข้อ

### กติกาทั่วไป

| เรื่อง | กติกา |
|---|---|
| `id` ทุกชนิด | ขึ้นต้นด้วยรหัสวิชา เช่น `sci-u1`, `sci-l01`, `sci-n01`, `sci-q001` (a-z 0-9 และ `-`) นำเข้าซ้ำด้วย id เดิม = แก้ของเดิม |
| เลขบท `no` | นับต่อเนื่องทั้งวิชา ไม่ซ้ำ (ตรงกับ `?l=` ใน URL) |
| บล็อกเนื้อหา | `heading` `paragraph` `figure` (image/video) `callout` `steps` `checklist` — ไม่ต้องมีครบทุกชนิด แต่ละหน้ามี ≥ 1 บล็อก |
| ข้อความ | ข้อความธรรมดาเท่านั้น ห้ามแท็ก HTML (สูตรอย่าง `pH < 7` ใช้ได้) ขึ้นบรรทัดใหม่ด้วย `\n` |
| รูป/วิดีโอ | ที่อยู่ต้องเป็น `https://…` **หรือไฟล์ในโฟลเดอร์ `assets/` ของเว็บเอง** (ดูหัวข้อ "ภาพและวิดีโอ" ข้างล่าง); รูปต้องมี `alt` |
| โจทย์ `mcq` | ตัวเลือก 2–6 ข้อ (`id` a, b, c…) + `correct` + `explanation` (ต้องมี ไม่งั้นเผยแพร่ไม่ได้); ใช้กับ `quiz` และ/หรือ `mock` |
| โจทย์ `open` | โจทย์ + `solution` (เฉลยและวิธีคิด); ใช้กับ `practice` เท่านั้น ผู้เรียนกดทำถูก/ผิดเอง |
| `tier` | `standard` ทุกแพลนเห็น; `advanced` เฉพาะ PLUS/MAX (เป็นข้อพิเศษ) |
| `exp` (โจทย์) | EXP ที่ข้อนั้นให้เมื่อตอบถูกใน Quiz และ Mock (0–1000, ไม่ใส่ = 5) ตั้งต่อข้อได้ เช่น ข้อยากให้มากกว่า |
| `starValue` | **ไม่ใช้แล้ว** (ดาวคิดจากเปอร์เซ็นต์ที่ตอบถูกใน Mock) ยังใส่ได้เพื่อให้ไฟล์เก่านำเข้าได้ |
| `quizPassPct` / `passPct` | เกณฑ์ผ่าน Quiz: ของบท (ไม่ใส่ = 50) และของชุดเดียว (`passPct` ในกิจกรรม Quiz); `null` = ทำแล้วผ่านเลย |
| Mock | `questionCount` ข้อ สุ่มจากโจทย์ `uses:["mock"]`; ต้องมีโจทย์ standard ที่เผยแพร่แล้วอย่างน้อยเท่าจำนวนข้อ; `timeBonusPct` = โบนัสดาวจากความเร็ว (ค่าเริ่มต้น 25, 0 = ไม่คิดเวลา); `maxStars` = ดาวเมื่อตอบถูกหมด (1–100, ไม่ใส่ = 10; ดาว = `maxStars` × % ที่ตอบถูก แล้วบวกโบนัสเวลา); `exp` = EXP เมื่อทำข้อสอบเสร็จแม้ไม่ถูกสักข้อ (0–1000, ไม่ใส่ = 20) |
| `exp` (กิจกรรม) | EXP เมื่อทำวงกลมนั้นเสร็จ: เนื้อหา = จบเนื้อหา, Quiz = ทำชุดเสร็จ (บวกกับ EXP ของข้อที่ตอบถูก), Practice = ให้ผลครบทุกข้อของชุด (0–1000, ไม่ใส่ = 10) |
| ทำซ้ำ | วงกลมที่เคยทำเสร็จแล้ว ทำอีกได้ EXP **ครึ่งเดียว** (ปัดลง) เสมอ; ดาวไม่ถูกหาร |

### ภาพและวิดีโอ (เนื้อหา โจทย์ Quiz / Practice / Mock และตัวเลือก)

- **ในเนื้อหา**: บล็อก `figure` — `{ "type": "figure", "kind": "image" | "video", "url": "…", "alt": "…", "caption": "…" }`
- **ในโจทย์**: `"media": [ { "kind": "image", "url": "…", "alt": "…", "caption": "…" } ]` (ไม่เกิน 3 ชิ้นต่อข้อ ใช้ได้ทั้ง Quiz, Practice และ Mock)
- **ในตัวเลือก**: `"choices": [ { "id": "a", "text": "ภาพ ก", "image": { "url": "…", "alt": "…" } } ]` (ยังต้องมี `text` เป็นป้ายของตัวเลือก)
- **ที่อยู่ของสื่อ** มี 2 แบบ:
  1. `https://…` — ภาพ/วิดีโอจากเว็บอื่นที่คุณมีสิทธิ์ใช้ (ตรวจลิขสิทธิ์เอง เช่น Wikimedia Commons ที่เป็น CC0 / CC BY ใส่เครดิตใน `caption`)
  2. `assets/study/<รหัสวิชา>/<ไฟล์>` — ไฟล์ที่ **อยู่ในโปรเจกต์หน้าเว็บเอง** (โฟลเดอร์ `assets/study/sci/` มีตัวอย่าง SVG) ต้อง commit/push ไฟล์นั้นไปพร้อมหน้าเว็บ ชื่อไฟล์ใช้ a-z 0-9 `. _ - ~` ไม่มีช่องว่าง
- **วิดีโอ**: ไฟล์ `.mp4 .webm .ogg .mov` เล่นในหน้า; ลิงก์ **YouTube** (`youtube.com/watch?v=…`, `youtu.be/…`) และ **Vimeo** ฝังให้อัตโนมัติ (ใส่ `?t=90` เพื่อเริ่มที่วินาทีที่ 90); ลิงก์วิดีโอเว็บอื่นเป็นปุ่ม "เปิดวิดีโอ" เปิดแท็บใหม่
- ภาพเล็กในหน้าเนื้อหาแตะเพื่อขยายได้; แนะนำภาพแนวนอนกว้างไม่เกิน ~1200px (ไฟล์ SVG/WebP เบาที่สุด) และข้อความในภาพควรใหญ่พอให้อ่านบนมือถือ (กว้าง ~340px)
- **ภาพในโจทย์ห้ามมีข้อความที่บอกคำตอบ** และ `alt` ควรบอกว่าเห็นอะไร ไม่ใช่เฉลย

### ไฟล์เนื้อหาจำลองวิทยาศาสตร์ (สำหรับทดสอบระบบบน Preview)

[examples/study-content.sci-mock.json](examples/study-content.sci-mock.json) คือวิชา `sci` ที่ใช้นำเข้าได้เลย (รุ่น 2): **2 หน่วย 4 บท 17 กิจกรรม** — เนื้อหา 8 ชุด (2–3 หน้าต่อชุด มีภาพ SVG และวิดีโอ), Quiz 5 ชุด (บทที่ 4 มี Quiz 2 ชุด), Practice 4 ชุด

ภาพประกอบอยู่ที่ [assets/study/sci/](../assets/study/sci/) (ต้อง push ไปพร้อมหน้าเว็บ) วิดีโอเป็นไฟล์ CC0 จาก Wikimedia Commons

## 2. ขั้นตอนนำเข้า

ต้องล็อกอินเป็นบัญชีที่ `role = admin` เปิดหน้า Study (เช่น beta-study.headface.app) แล้วเปิด Console ของเบราว์เซอร์
(เบราว์เซอร์จะแนบ cookie และ CSRF ให้เอง ไม่ต้องใส่รหัสใด ๆ)

```js
// ตั้งค่าครั้งเดียวต่อแท็บ
const { apiFetch } = await import('/js/api-client.js');
const admin = async (action, body) => (await apiFetch(`/api/study/admin/${action}`, { method: 'POST', body: JSON.stringify(body) })).json();

// ก๊อปปี้เนื้อหาทั้งไฟล์ไว้ในคลิปบอร์ด แล้ว
const file = JSON.parse(await navigator.clipboard.readText());
```

1. **ลองก่อน (ไม่เขียนอะไร)** — ดูว่าผิดตรงไหน และจะสร้าง/แก้กี่แถว
   ```js
   console.log(await admin('import', { ...file, dryRun: true }));
   ```
   ถ้า `success: false` แต่ละข้อผิดมี `path` ชี้ตำแหน่ง (เช่น `subject.questions[3].correct`) แก้ไฟล์แล้วลองใหม่ — **ผิดข้อเดียวไม่มีอะไรถูกบันทึก**
2. **นำเข้าจริง** — ทุกอย่างเป็น Draft นักเรียนยังไม่เห็น
   ```js
   console.log(await admin('import', { ...file, dryRun: false }));
   ```
3. **ตรวจ** — ดูโครงทั้งหมดรวม Draft, จำนวนโจทย์ต่อบท และสิ่งที่ยังขวางการเผยแพร่
   ```js
   console.log(await admin('overview', { subjectId: 'sci' }));   // publishable / blockers
   ```
   อ่านเนื้อหา โจทย์ เฉลย และคำอธิบายทีละข้อตามหัวข้อ 3 ก่อนไปขั้นถัดไป
4. **ส่งรีวิว → เผยแพร่** (`cascade: true` เลื่อนทั้งวิชารวมหน่วย บท โจทย์ และ Mock พร้อมกัน)
   ```js
   await admin('status', { entity: 'subject', id: 'sci', to: 'in_review', cascade: true, reason: 'ตรวจเนื้อหาแล้ว' });
   await admin('status', { entity: 'subject', id: 'sci', to: 'published', cascade: true, reason: 'อนุมัติเผยแพร่' });
   ```
   ไม่ผ่านเกณฑ์ → `PUBLISH_BLOCKED` พร้อมรายการที่ต้องแก้ และไม่มีอะไรเปลี่ยน
5. **แก้ภายหลัง**: แก้ไฟล์แล้วนำเข้าซ้ำ แถวที่เปลี่ยนกลับเป็น Draft ใหม่ ถ้าแถวนั้นเผยแพร่อยู่ ระบบจะหยุดและถามก่อน (`WOULD_UNPUBLISH`) ให้ใส่ `confirmUnpublish: true` เมื่อยอมให้แถวนั้นหายจากฝั่งนักเรียนจนกว่าจะเผยแพร่ใหม่
   ซ่อนแถวชั่วคราวหรือเลิกใช้: `admin('status', { entity: 'lesson', id: 'sci-l05', to: 'draft' })` หรือ `to: 'archived'` (จาก published)

ทุกการนำเข้าและเปลี่ยนสถานะถูกบันทึกประวัติ (ใคร เมื่อไร เหตุผล พร้อมสำเนาเนื้อหา) ในตาราง `study_content_revisions`

## 3. เช็กลิสต์ตรวจเนื้อหาที่ AI ร่าง (Blueprint ข้อ 10.4)

AI ช่วยร่างได้ แต่ **ผลลัพธ์ของ AI คือร่างที่รอตรวจ** ไม่ใช่เนื้อหาที่ถูกต้องโดยอัตโนมัติ ก่อนกดเผยแพร่ให้ตรวจ

- [ ] เนื้อหาถูกต้องตรงตามหลักสูตรของวิชา/ระดับชั้นนั้น (สูตร ตัวเลข ศัพท์ ตัวอย่าง)
- [ ] เฉลยของทุกข้อถูกจริง (ลองทำเองหรือให้คนที่สอนวิชานั้นดู) และมีตัวเลือกที่ถูกเพียงข้อเดียว
- [ ] คำอธิบายเฉลยอธิบายเหตุผล ไม่ใช่แค่ย้ำคำตอบ และไม่ขัดกับเนื้อหาในบท
- [ ] โจทย์ในบทสอดคล้องกับเนื้อหาของบทนั้น (Quiz วัดสิ่งที่สอนในบท)
- [ ] ระดับความยาก (`easy/medium/hard`) และ `topic` เหมาะสม — `topic` ใช้วิเคราะห์จุดแข็ง/จุดอ่อน ควรใช้ชื่อเดียวกันสำหรับเรื่องเดียวกัน
- [ ] โจทย์ที่ใช้กับ Mock ครอบคลุมทั้งวิชา และไม่ซ้ำกับ Quiz แบบข้อต่อข้อ (Quiz กับ Mock ประเมินคนละจุดประสงค์)
- [ ] รูป/วิดีโอเปิดได้ มีสิทธิ์ใช้งาน และ `alt` อธิบายภาพจริง
- [ ] ลองดูหน้าบทเรียนบนมือถือแล้วอ่านง่าย ไม่มีข้อความตกหล่น

## 4. ข้อควรรู้

- ทดสอบบน Preview (beta-study) ก่อนเสมอ ฐานข้อมูล Preview แยกจาก Production
- ยังไม่มีหน้าจอให้แก้เนื้อหา (Content Studio อยู่ใน Phase 3) การแก้ทำที่ไฟล์แล้วนำเข้าซ้ำ
- แก้หน้าเนื้อหา/ชื่อ/ลำดับกิจกรรมของบท → บทนั้นกลับเป็น Draft (ต้อง `confirmUnpublish: true` ถ้าเผยแพร่อยู่); เพิ่มโจทย์เข้ากิจกรรมที่มีอยู่แล้ว **ไม่** ทำให้บทกลับเป็น Draft
- ความคืบหน้าของนักเรียนผูกกับ id ของกิจกรรม: เปลี่ยน id กิจกรรมที่มีคนเรียนไปแล้ว = กิจกรรมนั้นเริ่มนับใหม่ จึงควรคง id เดิมไว้เมื่อแก้ไฟล์
- วิชาที่ยังไม่เผยแพร่แสดงเป็น "เร็ว ๆ นี้" ในหน้า Home/Subjects โดยอัตโนมัติ
- หน้านักเรียนใช้ได้ครบแล้ว: เส้นทางวงกลมของวิชา, ชุดเนื้อหาหลายหน้า (จำหน้าที่อ่านถึง), ทำเครื่องหมายจบเนื้อหา, Quiz (ตรวจรายข้อ), Practice, Mock Exam (จับเวลา/ตรวจ/ดาวฝั่ง server) และผลการเรียนรายวิชา — โจทย์ที่นำเข้าไว้ใช้ได้ทันทีเมื่อ Published
- จำนวนโจทย์ที่ควรมีให้ใช้งานได้จริง: **Quiz แต่ละชุด (node)** อย่างน้อยเท่า `quizSize` (ไม่ใส่ = ของบท; ไม่ใส่ = 5) และอย่างน้อย 1 ข้อ ไม่งั้นเผยแพร่ไม่ได้ (`QUIZ_NODE_EMPTY`; Practice เหมือนกัน `PRACTICE_NODE_EMPTY`), Mock อย่างน้อยเท่า `questionCount` ใน pool standard (ถ้าไม่พอ ชุดจะแสดง "ยังไม่เปิดให้สอบ"); ยิ่งมีโจทย์มากกว่าที่ใช้ ยิ่งสุ่มได้หลากหลาย
- จุดแข็ง/จุดอ่อนในหน้าผลการเรียนจะเริ่มสรุปเมื่อนักเรียนตอบหัวข้อเดียวกันครบ 5 ข้อ ดังนั้นตั้งชื่อ `topic` ให้สม่ำเสมอ (เรื่องเดียวกันใช้ชื่อเดียวกันทั้ง Quiz และ Mock)
